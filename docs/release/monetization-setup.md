# 収益化セットアップ手順書（AdMob / アプリ内購入）

MAKE10 のコードには広告と課金がすでに実装されている。しかし**ストア側の設定と
対で初めて動く**ため、この手順を終えるまでは公開しても収益が出ないか、購入が
その場で失敗する。

現状:

| 項目 | 状態 |
| --- | --- |
| AdMob のアプリ ID / 広告ユニット ID | **設定済み**（2026-09-01、Android 分のみ。A-1 〜 A-4 完了） |
| AdMob のストアリンクと審査 | **未**（A-6。ここを通るまで本番広告は出ない） |
| Play Console の課金商品 | **未作成** |
| お支払いプロファイル | 未確認 |
| iOS の AdMob ID | **未取得**（`AdUnitIds` が `Platform.isAndroid` で分岐済みのため、Android 単独リリースの間は不要。A-7） |

## 全体の順序

前後関係があるので、この順に進める。

```
0. Play Console で「アプリを作成」する
   └ これが無いと AAB のアップロードも課金商品の作成も画面に入れない
1. AdMob でアプリと広告ユニットを作る            （A-1 〜 A-3）【完了】
2. 受け取った ID をコードに書き写す              （A-4）【完了】
3. AAB をビルドして Play の内部テストに上げる    （B-2）
   └ 課金商品は「BILLING 権限を宣言したビルド」が上がっていないと作れない
4. Play Console で課金商品を作って有効化する      （B-3, B-4）
5. ライセンステスターを登録して実機で通す          （B-5, B-6）
6. 製品版として審査に出す → 公開
7. AdMob でアプリを Play のリスティングとリンクする（A-6）
   └ ここから AdMob の審査（通常2〜3日）。通って初めて本番の広告が出る
```

**本番の広告が出るのは 7 が終わったあと。** コードに本番 ID を入れただけでは
まだ出ない。公開直後に広告が出ないのは異常ではないので、実装を疑う前に
A-6 を読むこと。

# A. AdMob の本番 ID（Android は設定済み）

Android の本番 ID は 2026-09-01 に受領し、コードにもマニフェストにも反映済み
（`AdUnitIds.androidProductionIdsConfigured` が true）。**A-1 〜 A-4 は完了して
いる。** ここから先に残っているのは A-5 の実機確認と A-6 のストアリンクだけ。

A-1 〜 A-4 は、ID を取り直すときと iOS 版を出すときのために残してある。

**本番 ID を入れただけでは、まだ本物の広告は出ない。** ストアで公開し、AdMob で
リンクし、AdMob の審査を通るまで配信は制限される（A-6）。

## A-1. AdMob アカウントを用意する

1. <https://admob.google.com/> にログインする（Google アカウントでよい）
2. 初回はお支払い情報・住所・税務情報の入力を求められる。**ここを埋めないと
   支払いは受け取れない**が、広告の配信自体は先に始められる

## A-2. アプリを登録する

1. サイドバーの **アプリ → アプリを追加**
2. プラットフォームは **Android**
3. 「アプリはアプリストアに公開されていますか？」→ **いいえ**
   Play で未公開でも登録でき、アプリ ID もその場でもらえる。
   公開したあとに A-6 でリンクし直す
4. アプリ名は `MAKE10` でよい
5. 作成後、**アプリ → すべてのアプリを表示** の一覧に出る
   **アプリ ID**（`ca-app-pub-XXXXXXXXXXXXXXXX~ZZZZZZZZZZ` の形。区切りは `~`）を控える

## A-3. インタースティシャル広告ユニットを作る

1. 対象アプリを開き、サイドバーの **広告ユニット → 広告ユニットを追加**
2. フォーマットは **インタースティシャル**
3. 名前は `make10-interstitial` など、あとで分かるもの
4. 作成すると**広告ユニット ID**（`ca-app-pub-XXXXXXXXXXXXXXXX/YYYYYYYYYY` の形。
   区切りは `/`）が表示される。控える

> `~` と `/` を取り違えやすい。**アプリ ID は `~`、広告ユニット ID は `/`**。

## A-4. コードへの反映（完了済み・現在の構成）

定義元は `lib/monetization/ads/ad_unit_ids.dart`。現在の値:

| 定数 | 値 |
| --- | --- |
| `_prodAndroidAppId` | `ca-app-pub-2873615858472032~3841448717` |
| `_prodAndroidInterstitialUnitId` | `ca-app-pub-2873615858472032/2546502748` |
| `androidProductionIdsConfigured` | `true` |

`android/app/src/main/AndroidManifest.xml` の
`com.google.android.gms.ads.APPLICATION_ID` にも同じアプリ ID が入っている。
マニフェストは起動時に読まれる静的ファイルで Dart から差し替えられないため、
**片方だけ変えないこと。** ズレは `test/platform/manifest_xml_test.dart` が検知する。

`interstitialUnitId` は `Platform.isAndroid` で分岐し、iOS では常にテスト ID を
返す。`ios/Runner/Info.plist` も自分のテスト ID を直接持っていて、Android の値は
参照しない。

ID を取り直すときは、上の3つとマニフェストを同時に直して `flutter test` を通す。

> **XML コメントにハイフンを2つ続けて書かないこと。** 仕様違反でパーサが弾き、
> Android ビルドだけが落ちる。過去に一度踏んでいる。

### 一時的にテスト広告へ戻したいとき

`androidProductionIdsConfigured` を `false` にすれば、ID を消さずに Android だけ
テスト広告へ切り戻せる。

## A-5. 実機で確認する（重要な注意あり）

本番 ID に切り替えると、**表示されるのは本物の広告**になる。

> **自分で自分の広告をクリックしないこと。** 無効なトラフィックと判定され、
> AdMob アカウントが停止されることがある。動作確認のあいだは、自分の端末を
> AdMob の**テストデバイス**として登録しておく（AdMob の
> 設定 → テストデバイス、または実機の初回起動時にログへ出る
> `Use RequestConfiguration.Builder.setTestDeviceIds(...)` の ID を登録する）。
> テストデバイスとして登録すれば、本番 ID のままテスト広告が返る。

確認する内容:

- [ ] プラクティスで3問クリアすると全画面広告が出る
- [ ] 4問目以降、次は3問後に出る（カウンタがリセットされている）
- [ ] タイムアタックのリザルト画面で広告が出る
- [ ] タイムアタックの**プレイ中**には出ない
- [ ] 広告を閉じたあと、ゲームが正常に続く
- [ ] 機内モードでも広告なしで普通に遊べる

## A-6. 公開後に Play とリンクする（ここまで本番広告は出ない）

**AdMob が本番の広告を配信するには、3つ揃う必要がある。**

1. アプリがストアで**公開**されている（ユーザーが入手できる状態）
2. AdMob 側でそのアプリを**ストアのリスティングにリンク**している
3. AdMob の**アプリ審査**を通過して「準備完了」になっている

手順:

1. Play で製品版を公開する
2. AdMob の **アプリ → アプリの設定** から Google Play のリスティングとリンクする
3. ステータスが「準備中」に変わり、審査が自動で始まる。**通常2〜3日**、
   長引くこともある
4. 「準備完了」になると通常の配信が始まる

> **公開直後に広告が出ないのは正常。** リンク前・審査中のアプリは配信が
> 制限される。実装を疑う前に AdMob 側のアプリの準備状況を確認すること。
> AdMob アカウント自体の初回確認にも、通常24時間・まれに2週間ほどかかる。

## A-7. iOS を出すときにやること（今は不要）

`AdUnitIds` は `Platform.isAndroid` で分岐していて、iOS では常にテスト ID を返す。
`Info.plist` も Android の値を参照しない。**Android 単独リリースの間、iOS 側を
触る必要はない。**

iOS 版を出すときに必要になるのは:

1. AdMob で **iOS 用のアプリ**を登録し、iOS のアプリ ID と広告ユニット ID を得る
   （AdMob の ID はプラットフォームごとに別物で、Android の値は使い回せない）
2. `AdUnitIds` に `_prodIosAppId` / `_prodIosInterstitialUnitId` と iOS 用の
   有効化フラグを足す
3. `ios/Runner/Info.plist` の `GADApplicationIdentifier` を iOS のアプリ ID に更新する

# B. Play Console のアプリ内購入を作る

商品 ID の定義元は `lib/monetization/billing/product_ids.dart`。
**Play Console 側の ID を1文字も違わずに一致させる**こと。違うと
`queryProductDetails` が何も返さず、購入ボタンが無反応になる。

| 商品 ID | 種別 | 価格 | Play Console の場所 |
| --- | --- | --- | --- |
| `make10_noads_lifetime` | 1回限りの購入 | ¥980 | 収益化 → 商品 → アプリ内アイテム |
| `make10_noads_monthly` | 定期購入（ベースプラン `monthly`） | ¥300 / 月 | 収益化 → 商品 → 定期購入 |

## B-1. お支払いプロファイルを設定する

Play Console の **設定 → お支払いプロファイル**。これが未設定だと課金商品の
作成画面そのものに入れない。銀行口座と本人確認が必要で、**審査に数日かかる
ことがある**ので、他の作業より先に着手しておくとよい。

## B-2. 先に AAB を1本アップロードする

前提として、Play Console に**アプリのエントリが作成済み**であること
（Play Console → アプリを作成）。アプリが無いとアップロード画面にも
課金商品の画面にも入れない。

課金商品を作るには、`com.android.vending.BILLING` 権限を宣言したビルドが
Play に上がっている必要がある。この権限は `in_app_purchase` プラグインが
マニフェストマージャ経由で自動的に足すので、こちらで書くものはない。

1. GitHub の Actions →「Build the Android release bundle」を実行して `.aab` を得る
2. Play Console → **テスト → 内部テスト → 新しいリリースを作成**
3. `.aab` をアップロードして、リリースを保存（公開まで進めなくてよい）

## B-3. 買い切り（`make10_noads_lifetime`）を作る

1. **収益化 → 商品 → アプリ内アイテム → アイテムを作成**
2. 入力:
   - アイテム ID: `make10_noads_lifetime` （**作成後は変更も再利用もできない**）
   - 名前: `広告を消す（買い切り）`
   - 説明: `一度購入すると、以後この端末で広告が表示されなくなります。`
   - 価格: ¥980
3. **保存したあと「有効にする」を押す。** 作成しただけでは購入できない
4. 対象国／地域に日本が含まれていることを確認する

## B-4. 定期購入（`make10_noads_monthly`）を作る

定期購入は「定期購入 → ベースプラン → 特典」の3階層になっている。
**ベースプランを作って有効化するところまでやらないと、アプリから見えない。**

1. **収益化 → 商品 → 定期購入 → 定期購入を作成**
2. 入力:
   - アイテム ID: `make10_noads_monthly`
   - 名前: `広告を消す（月額）`
3. 保存したら、その定期購入の中で **ベースプランを追加**
   - ベースプラン ID: `monthly`
   - タイプ: **自動更新**
   - 請求期間: **1 か月**
   - 価格: ¥300
4. **ベースプランを「有効にする」**（定期購入本体とベースplanの両方）
5. 特典（無料トライアルなど）は任意。今は作らなくてよい

> ID は「数字または小文字で始まり、40文字以内」という制約がある。
> `make10_noads_monthly` / `monthly` はどちらも条件を満たしている。

## B-5. ライセンステスターを登録する

実際に課金せずに購入フローを通すために必要。

1. Play Console の**左上のアプリ一覧に戻り**、**設定 → ライセンステスト**
   （アプリごとではなく、デベロッパー アカウント全体の設定）
2. テストに使う Google アカウントのメールアドレスを追加する
3. ライセンスのレスポンスは `RESPOND_NORMALLY` のままでよい

さらに、そのアカウントを**内部テストのテスターにも追加**する
（テスト → 内部テスト → テスター）。ライセンステスターに入れただけでは
アプリを受け取れない。

## B-6. 実機で購入を通す

1. 内部テストのオプトイン URL を、テスターのアカウントが入った端末で開いて参加する
2. **Play ストア経由でインストールする**
   （`adb install` した野良ビルドでは購入できない。署名とバージョンが
   Play 上のものと一致している必要がある）
3. アプリ内の「広告を消す」画面を開く

確認する内容:

- [ ] 2つの商品が価格つきで表示される（`¥300` / `¥980`）
- [ ] 購入ダイアログに「テスト カード、常に承認」が出る（＝テスト購入になっている）
- [ ] 購入後、広告が出なくなる
- [ ] アプリを再起動しても広告が出ないまま（エンタイトルメントが永続化されている）
- [ ] 「購入を復元」で復元できる
- [ ] 定期購入は Play ストアのアプリ → 定期購入から解約でき、解約後に広告が戻る

## B-7. うまくいかないときのチェックリスト

「商品が表示されない」は、ほぼこの7つのどれか。

1. 商品を**有効化**していない（作成しただけになっている）
2. 商品 ID が `product_ids.dart` と1文字でも違う
3. 定期購入の**ベースプランを作っていない／有効化していない**
4. BILLING 権限を含むビルドが Play にアップロードされていない
5. 端末に入っているのが Play 経由でないビルド（署名・バージョンの不一致）
6. テスターのアカウントで Play ストアにログインしていない
7. 商品を有効化した直後（反映まで数時間かかることがある）

「価格は出るが購入が失敗する」場合は、お支払いプロファイル未設定か、
ライセンステスターに登録していないアカウントで試している可能性が高い。
